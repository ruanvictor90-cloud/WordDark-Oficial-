GOVERNANÇA / PROTEÇÃO

Segurança e acesso

Controle local, proteção de dados e limites explícitos.

◇

Bloqueio local

O cofre local usa uma frase secreta para derivar uma chave criptográfica. Os registros do darkHub são criptografados antes de serem gravados no armazenamento local.

⌁

Conexões externas

Nenhuma conexão externa está ativa. Integrações futuras precisarão de identidade autenticada, escopo mínimo, revogação e validação do lado servidor.

Desativadas por padrão
▤

Trilha de auditoria

Eventos relevantes são registrados dentro do cofre criptografado. A trilha local não substitui logs remotos resistentes a adulteração.

⬡

Limites de confiança

O código web pode ser inspecionado e alterado por quem controla o dispositivo. O bloqueio local protege contra acesso casual, mas não substitui autenticação de servidor nem armazenamento seguro nativo.

Proteção local, não servidor
POLÍTICA

Regras aplicadas

  • Não guardar senhas de serviços, tokens ou chaves de API no app.
  • Não executar scripts, plugins ou código arbitrário de projetos criados.
  • Não publicar, empacotar ou integrar sem ação explícita do operador.
  • Separar análise registrada de análise realmente executada e comprovada.
  • Bloquear automaticamente após inatividade e ao sair da aba.
  • Dados locais criptografados; nenhuma sincronização entre dispositivos.

DARKHUB / ACESSO PROTEGIDO

Cofre local

Crie uma frase secreta para proteger os dados deste dispositivo.

Use a frase secreta original do backup. A restauração substitui os dados locais atuais após a validação criptográfica.

A frase secreta não pode ser recuperada pelo darkHub. Se você perdê-la, os dados criptografados locais não poderão ser abertos. Guarde o backup e a frase secreta em locais seguros e separados.
